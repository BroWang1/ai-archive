# MiniCPM-V-4.7-1B-DSpark

`MiniCPM-V-4.7-1B-DSpark` is a [DSpark](https://arxiv.org/abs/2607.05147) draft checkpoint trained for exact pairing with [MiniCPM-V-4.7-1B](https://huggingface.co/openbmb/MiniCPM-V-4.7-1B) and its tokenizer.


## Model Specification

| Property | Value |
|---|---|
| Target model | [MiniCPM-V-4.7-1B](https://huggingface.co/openbmb/MiniCPM-V-4.7-1B) |
| Draft layers | 5 |
| Draft parameters | 213,547,777 |
| Draft tokens per forward pass | 15 |
| Target hidden-state layers | `[3, 7, 11, 15, 19]` |
| Checkpoint precision | BF16 |

## Training Recipe

Training responses were generated by [MiniCPM-V-4.7-1B](https://huggingface.co/openbmb/MiniCPM-V-4.7-1B) from a mixture of Vision & Text prompts.

| Setting | Value |
|---|---|
| Training sequences | 2M |
| Epochs | 6 |
| Optimizer | AdamW |
| Objective | CE + L1 + confidence loss |

## Evaluation

Acceptance length is defined as the total number of completion tokens divided by the total number of speculative verification steps. Evaluation uses natural EOS termination and `max_new_tokens=8192`.


| **Domain**            | **Accept Length** | 
| --------------------- | ----------------- |
| **Vision**            |                   |
| MMMU                  | 3.452             |
| MathVista             | 4.333             |
| CharXiv_reasoning_val | 4.452             |
| OCRBench              | 4.752             |
| **Text**              |                   |
| Math                  | 5.891             |
| Code                  | 5.347             |
| General               | 3.370             |



## Usage with vLLM

```bash
vllm serve \
  --model openbmb/MiniCPM-V-4.7-1B \
  --served-model-name MiniCPM-V-4.7-1B \
  --max-model-len 40960 \
  --max-num-batched-tokens 40960 \
  --max-num-seqs 1 \
  --attention-backend FLASH_ATTN \
  --mm-encoder-attn-backend FLASH_ATTN \
  --mm-processor-kwargs '{"downsample_mode":"4x"}' \
  --trust-request-mm-kwargs \
  --speculative-config '{"method":"dspark","model":"openbmb/MiniCPM-V-4.7-1B-DSpark","num_speculative_tokens":15,"enable_adaptive_verification":false}' \
  --default-chat-template-kwargs '{"enable_thinking":false}' \
```


## Usage with llama.cpp

Download the target model, its vision projector (`mmproj`), and this DSpark draft:

```bash
huggingface-cli download openbmb/MiniCPM-V-4.7-1B-gguf MiniCPM-V-4_7-1B-Q4_K_M.gguf mmproj-model-f16.gguf --local-dir ./1B-gguf
huggingface-cli download openbmb/MiniCPM-V-4.7-1B-DSpark-gguf dspark-MiniCPM-V-4_7-1B-Q8_0.gguf --local-dir ./1B-gguf
```

Run with speculative decoding (`-md` = draft, `--spec-type draft-dspark`). `llama-cli` handles **both** the vision projector and the draft:

```bash
llama-cli \
  -m ./1B-gguf/MiniCPM-V-4_7-1B-Q4_K_M.gguf \
  --mmproj ./1B-gguf/mmproj-model-f16.gguf \
  -md ./1B-gguf/dspark-MiniCPM-V-4_7-1B-Q8_0.gguf \
  --spec-type draft-dspark \
  --image image.jpg -p "Describe this image." \
  -ngl 99 -ngld 99 -fa on -c 8192
```

For a multimodal server:

```bash
llama-server \
  -m ./1B-gguf/MiniCPM-V-4_7-1B-Q4_K_M.gguf \
  --mmproj ./1B-gguf/mmproj-model-f16.gguf \
  -md ./1B-gguf/dspark-MiniCPM-V-4_7-1B-Q8_0.gguf \
  --spec-type draft-dspark --spec-draft-n-max 15 \
  -ngl 99 -ngld 99 -fa on -c 8192 --jinja --port 8080
```

Requires a llama.cpp build with the `dflash` architecture and the DSpark Markov head. The draft must be paired with the matching MiniCPM-V 4.7 1B target. Draft quantization only affects acceptance length (never the output), so pick the smallest quant that fits — `Q8_0` / `Q6_K` are good defaults.
